# Request

## 🌐 Документация по классу Request

Добро пожаловать в документацию по классу `Request`! 🎉 Этот PHP-класс, расположенный в пространстве имен `Request`, предназначен для выполнения HTTP-запросов к API с использованием cURL. Он предоставляет гибкий и удобный интерфейс для отправки GET, POST, PUT, DELETE и других запросов, поддерживая JSON, multipart/form-data и кастомные заголовки. Ниже вы найдете подробное руководство по использованию, описание методов и рекомендации по внедрению.

***

### 🚀 Обзор

Класс `Request` разработан для упрощения взаимодействия с внешними API, обеспечивая:

* Отправку HTTP-запросов с поддержкой различных методов 📡
* Автоматическую обработку заголовков и тела запроса 📋
* Парсинг JSON-ответов с обработкой ошибок 🔍
* Гибкую настройку через базовый URL и дефолтные заголовки ⚙️

Класс использует cURL для выполнения запросов, что делает его надежным и производительным. Он подходит для интеграции с любыми API, включая СДЭК, и может быть легко адаптирован под различные сценарии.

***

### 🛠️ Установка и настройка

Чтобы использовать класс `Request`, выполните следующие шаги:

1.  **Подключите класс**: Убедитесь, что файл класса включен в ваш PHP-проект.

    ```php
    require_once 'path/to/Request.php';
    ```
2. **Убедитесь в наличии cURL**: Проверьте, что расширение cURL включено в вашей конфигурации PHP.
3.  **Создайте экземпляр класса**: Передайте базовый URL API и, при необходимости, дефолтные заголовки.

    ```php
    use Request\Request;
    $request = new Request('https://api.example.com', [
        'Authorization' => 'Bearer your_token',
        'Content-Type' => 'application/json'
    ]);
    ```
4. **Используйте метод `send`**: Вызывайте метод `send` для выполнения запросов (подробности ниже).

***

### 📋 Методы и использование

Класс `Request` предоставляет один публичный метод `send` для выполнения запросов, а также несколько приватных вспомогательных методов для обработки URL, заголовков, тела запроса и ответа. Ниже описан основной метод и его использование.

#### 1. `__construct(string $baseUrl, array $defaultHeaders = [])` 🛠️

Инициализирует класс, устанавливая базовый URL и дефолтные заголовки.

* **Параметры**:
  * `$baseUrl` (string): Базовый URL API (например, `https://api.cdek.ru`).
  * `$defaultHeaders` (array): Ассоциативный массив дефолтных заголовков (по умолчанию пустой).
* **Возвращает**: Ничего
*   **Пример**:

    ```php
    $request = new Request('https://api.cdek.ru', [
        'Authorization' => 'Bearer your_token',
        'Content-Type' => 'application/json'
    ]);
    ```

***

#### 2. `send(string $method, string $endpoint, array $options = [], $body = null)` 📡

Отправляет HTTP-запрос к указанному endpoint и возвращает распарсенный ответ.

* **Параметры**:
  * `$method` (string): HTTP-метод (GET, POST, PUT, DELETE и т.д.).
  * `$endpoint` (string): Конечный путь API (например, `/v2/orders`).
  * `$options` (array): Опции запроса (включая `headers` для дополнительных заголовков и `multipart` для multipart/form-data).
  * `$body` (array|string|null): Тело запроса (массив для JSON, строка для других форматов, или null для GET).
* **Возвращает**: Массив с распарсенным ответом API или массив с ключом `raw_response` для не-JSON ответов.
* **Исключения**: `Exception` в случае ошибок cURL или API.
*   **Пример (GET-запрос)**:

    ```php
    $response = $request->send('GET', '/v2/orders?status=CREATED');
    print_r($response);
    // Вывод: Массив с данными заказов
    ```
*   **Пример (POST-запрос с JSON)**:

    ```php
    $data = [
        'recipient' => ['name' => 'Иван Иванов'],
        'packages' => [['weight' => 1000, 'length' => 30, 'width' => 20, 'height' => 10]]
    ];
    $response = $request->send('POST', '/v2/orders', [], $data);
    print_r($response);
    // Вывод: Массив с данными созданного заказа
    ```
*   **Пример (POST-запрос с multipart)**:

    ```php
    $multipart = [
        ['name' => 'file', 'contents' => fopen('file.txt', 'r')]
    ];
    $response = $request->send('POST', '/upload', ['multipart' => $multipart]);
    print_r($response);
    // Вывод: Ответ API
    ```

***

#### Приватные методы

Эти методы используются внутри класса и не предназначены для прямого вызова:

* `buildUrl(string $endpoint)`: Формирует полный URL, объединяя базовый URL и endpoint.
* `mergeHeaders(array $headers, $body, $multipart = null)`: Объединяет дефолтные и пользовательские заголовки, устанавливая `Content-Type` при необходимости.
* `formatBody($body, $multipart = null)`: Форматирует тело запроса (JSON для массивов, как есть для multipart или строк).
* `executeRequest(string $method, string $url, array $headers, $body)`: Выполняет cURL-запрос и возвращает сырой ответ.
* `parseResponse(string $response)`: Парсит ответ, преобразуя JSON в массив или возвращая сырой ответ, и проверяет наличие ошибок API.

### ⚠️ Лучшие практики

* **Валидация входных данных**: Проверяйте `$method` и `$endpoint` перед вызовом `send`, чтобы избежать некорректных запросов.
*   **Обработка ошибок**: Оборачивайте вызовы `send` в try-catch, так как метод может выбросить `Exception` при ошибках cURL или API.

    ```php
    try {
        $response = $request->send('GET', '/v2/orders');
        print_r($response);
    } catch (Exception $e) {
        echo "Ошибка: " . $e->getMessage();
    }
    ```
* **Заголовки**: Используйте `$defaultHeaders` в конструкторе для общих заголовков (например, авторизации) и добавляйте специфичные заголовки через `$options['headers']` при необходимости.
* **Multipart-запросы**: Для multipart/form-data передавайте данные в `$options['multipart']` в формате, совместимом с cURL (например, массив с ключами `name` и `contents`).
* **Логирование**: Внедрите логирование запросов и ответов для отладки и мониторинга. Например, сохраняйте `$url`, `$method`, `$body` и `$response`.
* **Кэширование**: Если API возвращает редко меняющиеся данные, рассмотрите кэширование ответов для оптимизации производительности.

***

### 🐛 Устранение неполадок

* **Ошибка cURL**: Если метод `send` выбрасывает исключение с сообщением "Ошибка cURL", проверьте:
  * Доступность API (`$baseUrl`).
  * Включено ли расширение cURL в PHP.
  * Корректность сети (например, наличие прокси или брандмауэра).
* **Ошибка API**: Если исключение содержит "Ошибка API", проверьте:
  * Правильность `$endpoint` и `$body`.
  * Соответствие заголовков требованиям API (например, `Authorization` или `Content-Type`).
  * Документацию API на предмет ожидаемой структуры запроса.
* **Некорректный JSON**: Если ответ не парсится как JSON, метод вернет массив с ключом `raw_response`. Проверьте формат ответа API и добавьте обработку для не-JSON данных.
* **Multipart-ошибки**: Убедитесь, что `$options['multipart']` содержит корректные данные (например, открытые файловые ресурсы для `contents`).
